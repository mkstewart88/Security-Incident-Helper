================================================================================
SECURITY INCIDENT RESPONSE AUTOMATOR - QUICK START GUIDE (v1.1.69)
================================================================================

Get Security Incident Response Automator running on a Windows workstation or
server in just a few minutes.

--------------------------------------------------------------------------------
1. PREREQUISITES
--------------------------------------------------------------------------------
- OS & Runtime: Windows 10 (1809+), Windows 11, or Windows Server 2016+ with
  Windows PowerShell 5.1 and .NET Framework 4.8+.
- Permissions: Appropriate administrative privileges in Active Directory,
  Microsoft Entra ID, and/or Google Workspace for your planned actions.
- Network: Direct access to a Domain Controller (TCP 389/636) and outbound
  HTTPS (TCP 443) for cloud operations.

--------------------------------------------------------------------------------
2. LAUNCH OR COMPILE
--------------------------------------------------------------------------------
Choose any of the three launch methods:

- Option A (Recommended): Double-click "Launch-IncidentAutomator.bat".
- Option B (PowerShell):
  powershell.exe -NoProfile -ExecutionPolicy Bypass -STA -File .\IncidentResponse-Automator.ps1
- Option C (Standalone .exe): Double-click "Compile-To-EXE.cmd" to build a
  portable IncidentResponse.exe.

Security Note: Review IncidentResponse-Automator.ps1 and accompanying scripts
before running them in production. See DISCLAIMER.md.

--------------------------------------------------------------------------------
3. INITIAL SETUP (TAB 1: 1. SETUP)
--------------------------------------------------------------------------------
1. Primary Profile Prompt (First Launch): Choose whether this environment is your
   Primary (Home) Domain Profile or if you are temporarily assisting another
   domain, then enter a profile name.
2. Test or Install Integrations: Use the three integration columns on Tab 1:
   - Active Directory: Click "Test Active Directory" (or "Switch AD Account /
     Domain" for non-joined workstations or alternate admin credentials).
   - Microsoft Graph: Run "1. Setup Microsoft Graph" (first time), then use
     "Test Microsoft Graph" or "Switch Graph Account".
   - Google GAM7: Run "2. Setup Google GAM7" (first time), then use "Test
     Google GAM7" or "Switch GAM Account".
3. Optional Credential Vault & Master Passphrase:
   - You can optionally save DPAPI-encrypted AD credentials per Domain Profile
     for automatic startup connection when plugged into that domain network.
   - Click "Master Passphrase" in the top-right header to require a startup
     passphrase across saved profiles (includes Change, Remove, and emergency
     "Remove Passphrase & All Creds" reset).

--------------------------------------------------------------------------------
4. BASIC INCIDENT CONTAINMENT WORKFLOW
--------------------------------------------------------------------------------
1. Locate & Verify (Tab 2): Search by name, username, or email (3+ chars),
   select the target user, review the four status cards, and check the identity
   confirmation box to unlock the action deck.
2. Contain (Tab 2): Run individual actions (Reset Password, Revoke 365 Sessions,
   Revoke Google Sessions, Disable Account) or "Run Full Playbook (1-Click)".
3. Deep Isolation & BEC Check (Tab 3): Block Entra sign-in, suspend Google
   accounts, wipe persistent MFA/OAuth grants, expire Kerberos tickets, and run
   "Audit M365 & Gmail Rules" to remediate suspicious forwarding rules.
4. Triage & Audit (Tabs 4 & 5): Pull and filter security events on Tab 4, and
   review or export local compliance logs on Tab 5.

For complete operator instructions, see README.txt or README.md.
